- Ruling：全新独立产品目录直接建立 feat/initial-diagnostics 开发分支，不额外创建关联worktree；没有既有主分支或用户代码需要隔离。成本：后续并行开发需另建worktree。
- Ruling：技能附带脚本依赖bash，而当前命令环境未提供bash；用Windows原生命令维护同等任务记录，不改变测试/提交门槛。
- Ruling：真实权限不足不阻塞纯逻辑和只读诊断开发，不扩大权限推断支持。Task0维持部分完成，业务验收不能因此标绿。
- Ruling：报告边界测试需要脱敏，先在报告模块实现最小脱敏，Task6扩展规则并复用，避免出现两套不一致实现。
- 构建工具首次启动提示安装ASP.NET开发证书；没有执行trust。后续设置DOTNET_GENERATE_ASPNET_CERTIFICATE=false。不删除没有前后基线的证书。
- NuGet在受限环境恢复失败，提升环境后仅执行依赖恢复成功，没有修改系统代理。
- 本机PowerShell禁止脚本，开发测试以子进程ExecutionPolicy Bypass运行仓库内已审阅脚本；不改变用户或计算机执行策略，产品不依赖永久放宽策略。
- 依照计划“首次执行先做M0及只读功能”，本阶段交付只读开发预览；Task3/5/6/10只实现基础子集，不将其勾选为整项完成。Task4的版本机制验证是修复门槛，不用空适配器或假支持来填补。
- 早期UI工作流状态与同意门禁放在Core/Workflow，窗口仅编排只读操作；尚未引入完整修复ViewModel，后续按实现计划扩展。
- 使用固定参数系统netstat读取TCP表；它与进程身份是非原子采集，整体Partial，不作为Confirmed占用证明。未采集的DNS/路由/WinHTTP明确列出。
- HTTP阶段只记录总耗时和HTTP结果，未把总耗时伪造为分阶段DNS/TCP/TLS耗时。ProcessDefault返回NotTested；当前仅HTTP无凭据显式代理，不自动降级SOCKS。
- 独立只读审查发现.env后缀/JSON字段漏检、失败重试状态问题；已先复现失败，再补回归修复。
- Ruling：四类适配器本轮只观察候选配置与安装元数据，不写未知磁盘结构；WorkBuddy官方网络面板不等于已知5.9.0文件字段，新Antigravity CLI文档不代替旧IDE/新桌面的业务机制。代价：真实修复解锁较晚，但避免破坏配置。
- Ruling：直接引用Tomlyn2.10.1(BSD-2-Clause)解析TOML，不手写语法；严格语义验证在反序列化前执行。net10目标无额外传递包；代价是维护一个运行依赖和上游边界，未因此开放TOML写入。
- Ruling：Windows模块引用产品本就使用的桌面框架，以使用标准ProtectedData(CurrentUser)，不手写DPAPI互操作或引入另一密码学NuGet库。沙箱缺用户资料时真实测试失败，正常用户上下文同一夹具通过，不改为明文。
- Ruling：默认候选读取拒绝UNC/设备/非固定盘/全部重解析路径；从根向下检查后才打开文件，防止未确认联网时SMB认证。代价：本地数据迁移junction也暂时未读取，明确记录而非建议用户撤销迁移。
- Ruling：RepairExecutor使用目标存储锁内返回的本次写入hash，不在解锁后读取hash作为“本次结果”；原始备份hash也与预览比对。现仅内存夹具验证，真实文件CAS和中断恢复未实现，不接UI写入。
- Final fixed：独立审查的远程路径问题，WindowsPathPolicy用例先红后绿，UNC和本地junction配置/备份拒绝集成通过；备份后取消问题用CancellationDuringBackupStopsBeforeMutation先红后绿。无复审代替测试。
- Ruling：中文中国版报告显示北京时间UTC+8，原始证据保持UTC；不改变操作系统时区。
- 第三阶段：IRepairTargetStore添加默认BindRecoveryAsync；实际文件存储只有验证受保护备份与计划摘要后才允许写入，内存夹具保持兼容。写入使用独占句柄，在锁内复核、保存Prepared日志、写入/刷新/回读、保存Completed日志；开始写入后完成有界操作，不以取消截断文件。
- 第三阶段：复用DPAPI/当前用户专属目录存储恢复日志，公开索引只有随机ID；新实例读取日志后只分类当前指纹，不自动恢复。配置文件原地写入不是掉电原子替换；保留不匹配状态和备份，禁止强制覆盖。真实版本注册仍为空，不把合成Antigravity夹具作为产品支持证据。
- 第四阶段：启动配置采用不含路径/参数/任意环境字典的最小记录；路径、参数和模式由已核实适配注册决定，保存用摘要确认、DPAPI加密。真实版本注册为空时短时入口明确拒绝，不通过读取配置隐式解锁。
- 第四阶段：复用测试辅助项目验证进程Exit与子进程环境，不用FailFast/WER，不发布该项目。环境观察进程等待父测试释放信号，避免PID返回后立即退出造成竞态。清除代理环境模式不宣称绕过TUN或应用内代理。
- 第五阶段：用户要求直接看到成品、不再询问；实现中文四页工作流与自包含试用包，沿用原目标，不因缺真实验收暗中扩大支持。WinINet系统代理写入仍有全用户影响，审查后按既有验收顺序在后端硬锁，而不是只加实验提示；不得以配置可读或模拟写入通过解锁。
- 第五阶段：WinINet读取FLAGS_UI观察静态/自动发现配置；残留代理计划只接受未管理、无PAC/自动发现、数字回环IP、连续两次明确拒绝连接，超时保持未知。发布包不改Windows、TUN、DNS或路由。
